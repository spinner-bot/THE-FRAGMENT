## 第 52 章：关键错误：把统计拟合当机制

### 52.1 错误的起点

ChatGPT 在早期把 Q5 描述为：

> 有若干“动态列”，每一行选择其中一列更新；需要找出选择下一列的规则。

这个描述与数据表面完全吻合：

- 每行确实只有一个非零位置变化；
- 变化位置确实形成一个序列；
- 这个序列确实有一阶转移、回返、长程相关等统计结构。

于是一个自然的研究计划是：

1. 统计位置转移矩阵；
2. 检验 Markov 阶数；
3. 找周期、回返间隔、最近更新时间；
4. 拟合一个“选择器”。

这套计划产生了大量真实但无关的规律。

### 52.2 哪些规律是真的

以下都是解题记录中报告过、并可从数据复核的性质：

- 相邻行恰好一个位置变化；
- 499 次更新可以分成 251 个连续区段；
- 某些区段长度与平方根有关；
- 位置序列有一阶转移偏好；
- `A→B→A` 的两步回返高于独立模型；
- 回返在间隔 2、4、8 上超额；
- “最近更新时间”对下一位置有 44%–53% 的预测力；
- 117 种排列中 87 种出现冲突，说明“最近更新时间顺序”不是充分状态。

这些结论没有一条是伪造的。问题在于：**它们描述的是输出，不是生成过程。**

### 52.3 为什么拟合会自我强化

假设真实过程是：

```text
第 n 行 = 把 n 放进 R(n) 对应的桶
```

那么从输出看：

- 每行只变一个桶（真）；
- 连续几个 n 可能落进同一个桶（真）；
- 桶的选择看起来有记忆（因为 R(n) 有局部结构）（真）；
- 某些间隔上回返更多（真）。

每一条统计规律都能被这个真实过程解释，但反过来不唯一。拟合模型会不断得到“70% 准确”“回返因子 2.17”“四阶差分成立”这样的正反馈，于是研究者会继续在同一框架内加参数，而不是换框架。

这就是**框架锁定**：不是没有证据，而是证据被错误地组织。

### 52.4 提示为什么没能救回来

七次提示的结果：

| 提示 | 回答 | 被否定的命题 |
|---:|---|---|
| 1 | F | 固定种子 PRNG 直接决定动态列 |
| 2 | F | 仅由六个当前值和固定常数决定下一列 |
| 3 | 无效 | 提问预设了“下一列选择器” |
| 4 | F | 稳定阶段参数由其余五值的平方根和决定 |
| 5 | F | 更新位置由随机抽样直接决定 |
| 6 | 无效 | 提问预设“最近更新时间顺序是输入” |
| 7 | 无法提供 | 问题仍围绕错误框架 |

提示 3 和 6 其实已经指向框架错误：它们不是说“这个公式不对”，而是说“这个问题本身问错了”。但 ChatGPT 把“无效”理解为“换一种问法”，而不是“换一个本体”。

提示 7 被拒绝，说明系统不愿意在“生成规则”层面继续给开放式提示。此时正确动作是停止拟合、回到数据的第一层（稀疏数组与编码），而不是继续构造新假设。

### 52.5 正确的问题长什么样

错误问题：

> 下一列由什么规则选择？

正确问题：

> 这一行整体是如何被计算出来的？

前者预设了“逐行动态更新”；后者允许“每行独立重算”。

一旦问出后者，就会自然去做：

1. 展开负数游程；
2. 观察非零位置固定；
3. 解三角数；
4. 发现每行只是多了一个元素；
5. 找 `n → 桶` 的映射。

这条路径不需要 Markov、不需要回返因子、不需要最近更新时间。

### 52.6 统计拟合仍然有用

这不是说统计无用。统计可以帮助：

- 发现“每行只变一个位置”；
- 发现“非零位置固定”；
- 发现“值随行单调增长”；
- 排除“独立随机列”等假设。

问题只在于：**统计只能提出候选，不能证明机制。** 机制必须能逐行复现原始字节。

### 52.7 这一章得到了什么

- 区分“数据的性质”和“生成它的规则”。
- 解释框架锁定如何让提示失效。
- 给出正确问题的形式。

## 第 53 章：提示系统的信息论

### 53.1 两套评分不要混淆

包内有两套独立的分数：

1. **`.entrance` 的进度分。** 0%、20%、40%、60%、80%、100% 对应 60、61、63、66、70、100。完成四题时是 70。
2. **Q5 提示系统的实时评分。** 初始 70，每次购买提示按“原价 × 60%（是非题折扣）”扣分。

实时评分的变化：

| 事件 | 提示原价 | 实扣 | 评分 |
|---|---:|---:|---:|
| 初始 | — | — | 70 |
| 提示 1 | 3 | 1.8 | 68.2 |
| 提示 2 | 5 | 3.0 | 65.2 |
| 提示 3 | 7 | 4.2 | 61.0 |
| 提示 4 | 9 | 5.4 | 55.6 |
| 提示 5 | 11 | 6.6 | 49.0 |
| 提示 6 | 13 | 7.8 | 41.2 |
| 提示 7 | 15 | 9.0（退还） | 41.2 |

原价序列是 3、5、7、9、11、13、15，每次加 2。是非题打六折，所以实扣是 1.8、3.0、4.2、5.4、6.6、7.8、9.0。

第 7 次提示被判定“无法提供”，积分退还，价格不涨。这是系统对“问题超出可回答范围”的处理，不是一次有效信息。

### 53.2 每条提示买到了多少信息

用信息论的粗糙口径看，一次 T/F 回答最多 1 bit；但实际价值取决于它排除了多大的假设空间。

| 提示 | 类型 | 排除的假设空间 | 信息价值 |
|---:|---|---|---|
| 1 | F | “固定种子 PRNG 直接选列”这一整类 | 高 |
| 2 | F | “六个当前值 + 常数决定下一列” | 高 |
| 3 | 无效 | 整个“下一列选择器”提问框架 | 很高（元信息） |
| 4 | F | 一个具体的平方根公式 | 中 |
| 5 | F | “随机抽样直接决定位置” | 高 |
| 6 | 无效 | “最近更新时间顺序是输入” | 很高（元信息） |
| 7 | 无法提供 | 无 | 0 |

“无效”不是 0 信息。它否定的不是命题真假，而是**提问前提**。提示 3 等于说：“你问‘下一列怎么选’这件事本身就有问题。”这是比 F 更强的信号，但它要求解题者愿意放弃整个本体。

### 53.3 为什么提示 7 无法提供

提示 7 仍然在问“生成规则是否使用某个隐藏状态”。系统连续两次判定“先入为主的错误”后，第三次直接拒绝提供。可能的原因：

- 问题仍然预设了一个不存在的“选择器”；
- 答案不是 T/F，而是“模型类别错了”；
- 系统只对可判定的具体命题给 T/F，对框架错误只给“无效”。

从信息设计看，这是合理的：如果系统继续回答“F”，解题者会以为“只差一个隐藏状态”，从而更深地锁进错误框架。拒绝提供，反而迫使解题者回到数据。

### 53.4 提示系统的真正成本

表面成本是 1.8–9.0 分。真实成本是**注意力**：

- 每次提示后，ChatGPT 都花 3–20 分钟围绕提示重构模型；
- 提示 4 的 F 让它撤回平方根公式，但没有撤回“动态列”框架；
- 提示 5 的 F 让它撤回随机抽样，但转向“确定性隐藏状态”，仍在同一框架；
- 提示 6 的无效让它转向“最近更新时间”，仍是同一框架。

七次提示合计只扣了 28.8 分，但把两小时引向了七个不同的统计子模型。**提示买的是排除，不是方向。**

### 53.5 如果重来，提示该怎么用

最优策略不是“少买”，而是“买能改变本体的提示”。

- 提示 1、2 值得买：它们排除了两个具体机制。
- 提示 3 出现“无效”时，应立即停止“选择器”语言，回到数据展开。
- 提示 4 之后不应再拟合平方根。
- 提示 6 出现第二次“无效”时，应意识到系统在说“你的问题类别错了”，而不是“再换一个特征”。

真正高价值的提示，应该直接问：

> 第 n 行的输出是否只由 n 决定，而不依赖第 n−1 行的状态？

这个问题一旦得到 T，整个动态框架就会立刻崩塌。但它也可能被判定“先入为主”，因为它预设了“索引驱动”这个候选。提示系统的边界正在这里：它能否定你想到的命题，不能替你想到没想到的命题。

### 53.6 这一章得到了什么

- 两套评分系统的区别。
- 七次提示的价格、扣分与信息类型。
- “无效”是元信息，不是零信息。
- 提示无法突破“未知的未知”。

## 第 54 章：如果重来：最短路径

### 54.1 总体路径

事后看，从 ZIP 到 Q5 答案的最短路径是：

```text
release/THE FRAGMENT.zip
→ incipit.7z / incipit.html            （读叙事，确认入口）
→ Let's go.7z / instruction.gz         （读规则，确认答案链）
→ P1：5050
→ Q2.zst → ITC2RECIPE 解密 → SHIT 层
→ SHIT.bz2 → 仿射递推 → K
→ Q3.7z → ITC2RECIPE 解密 → .entrance
→ P1-02C → P1-02B → P1-02A → README.7z
→ prompt.7z / puzzle.7z → Q1–Q4
→ Q5：展开 → 三角数 → 分组 → Collatz
```

每一层都有一个“最小充分动作”：

| 层 | 不要做 | 应该做 |
|---|---|---|
| 外层 ZIP | 不要先猜密码 | 先列目录，读 `incipit` 与 `instruction` |
| P1 | 不要写复杂脚本 | 直接算 `1+...+100` |
| ITC2RECIPE | 不要找现成工具 | 读文件头，按自描述格式实现 60 行解密器 |
| SHIT 层 | 不要被 README 的噪音带走 | 先解 `SHIT.bz2`，README 只取结构提示 |
| P2 | 不要迭代 10^18 次 | 用仿射递推闭式 |
| P3 嵌套 | 不要逐层猜扩展名 | 看文件头，按 gzip/bzip2/7z/ZIP 魔数处理 |
| Q1–Q4 | 不要过拟合 | 每題先找行长度规律，再找值公式 |
| Q5 | 不要建动态模型 | 先展开稀疏数组，再解三角数，再找桶键 |

### 54.2 Q5 的最短路径

如果只给 Q5 数据，不给任何提示，最短路径是：

1. **展开负数游程。** 得到 500×18 稀疏矩阵。
2. **确认支撑集。** 非零位置固定为 `{1,2,3,4,7,8,13,17}`。
3. **解三角数。** 每个非零值 `V` 写成 `T_t + s`，得到 `(l, s)`。
4. **验证统计含义。** `l` 是成员数，`s` 是成员和。
5. **找新成员。** 每行变化的桶，其 `s` 增量就是行号 `n`。
6. **建立映射。** 记录每个 `n` 进入哪个桶。
7. **识别 Collatz。** 观察 `n → 桶` 的值域与 `C(n)` 的分布，尝试 `C`，再尝试 `C^{C(n)-1}`。
8. **全量复现。** 500/500 行字节级比较。

如果第 3 步就卡住，可以先用第 5 步：直接跟踪每个桶的 `s` 增量，发现它总是行号 n；这会反过来提示 `(l, s)` 的含义。

### 54.3 时间估计

| 阶段 | 熟练解题者 | 首次接触 |
|---|---:|---:|
| 外层 + 说明书 | 10 分钟 | 30 分钟 |
| P1 + Q2 锁 | 20 分钟 | 1 小时 |
| SHIT + P2 数学 | 30 分钟 | 2 小时 |
| P3 + 嵌套 | 30 分钟 | 2 小时 |
| Q1–Q4 | 20 分钟 | 1 小时 |
| Q5 | 1–2 小时 | 数小时到数天 |

“熟练”指已经知道 ITC2RECIPE、仿射递推、三角数编码这些套路。首次接触的主要成本不是计算，而是**识别当前层属于哪种结构**。

### 54.4 最短路径上的三个岔路

1. **把 Q2.zst 当 7z。** 会浪费时间找密码；正确动作是看魔数 `28 B5 2F FD`。
2. **把 `P1-02B` 当纯文本。** 它可能是 base64 或多层编码；先做熵/字符集判断。
3. **把 Q5 当动态系统。** 这是最大岔路，会引出 Markov、回返、LRU 等一整套无关模型。

### 54.5 这一章得到了什么

- 一条按层组织的最短路径。
- 每层的“最小充分动作”。
- Q5 的八步反推法。
- 时间估计与三个主要岔路。

## 第 55 章：设计者复盘：结构即难度

### 55.1 设计目标

这个包要同时做到三件事：

1. **答案链清楚。** 每一题的答案是下一把锁的钥匙。
2. **结构本身是难度。** 不是把数学题塞进 ZIP，而是让“拆包”成为解题的一部分。
3. **每一层都有内容。** 没有纯装饰的文件；每个文件要么承载规则，要么承载误导，要么承载下一层。

### 55.2 结构如何承担难度

| 结构 | 承担什么 | 如果去掉会怎样 |
|---|---|---|
| 外层 ZIP + 两个 7z | 建立“这不是一个文件”的预期 | 变成单层压缩包，入口太直白 |
| `incipit.html` | 叙事入口，区分“故事”与“规则” | 挑战变成纯技术题 |
| `instruction.html` | 规则层，说明答案即钥匙 | 解题者不知道答案要拿来做什么 |
| ITC2RECIPE | 自描述锁，必须读格式 | 变成“找密码”，失去结构挑战 |
| SHIT 层 | 误导与噪音 | P2 变成纯数学题 |
| `.entrance` | 评分与提示系统 | 失去资源管理维度 |
| 三层嵌套目录 | 文件类型识别 | 变成一路 `7z x` |
| 五题数据 | 从观察到逆向的难度曲线 | Q5 失去铺垫 |
| Q5 | 程序逆向 | 整包缺少真正的终点 |

### 55.3 自描述锁的设计取舍

不用 7z 密码，是自己实现 `ITC2RECIPE`，原因在本书第 17 章已展开。核心取舍：

- **优点：** 格式可见、可推理、可独立实现；不需要外部工具；锁文件本身就是题面。
- **代价：** 安全性不高（XOR 流 + SHA-256 派生），但这不是加密产品，而是谜题。
- **关键：** 锁必须“自描述”。文件头告诉解题者用什么算法、密钥从哪里来、TAG 如何验证。没有这一步，解题者只能暴力猜。

### 55.4 答案链的设计

```text
P1 = 5050
  → 打开 Q2
Q2 的数学题 → K
  → 打开 Q3
Q3 的嵌套 → 五题
Q1–Q4 → 热身
Q5 → 终点
```

每一环都满足：

- 答案唯一且可验证；
- 答案格式明确（十进制、无空格）；
- 答案不是“猜出来的”，而是“算出来的”；
- 下一把锁不会因为答案格式差异而误判（规范化在锁内部完成）。

### 55.5 误导层的设计

包内有几类误导：

1. **`SHIT.README` 的可读噪音。** 拼写错误、自相矛盾、伪指令，迫使解题者判断“哪些句子是规则，哪些是气氛”。
2. **`the map.bmp`。** 17 字节，内容 `answer is the key`，是提示也是干扰。
3. **Q4/Q5 的嘲讽文本。** 1,010 字节，伪装成答案，实际是诱饵。
4. **`README.json` 的码点文本。** 可读但无空格，要求解题者做编码转换。
5. **`.entrance` 的评分表。** 看起来像程序，实际是静态文本。

好的误导不是“假文件”，而是“真文件但语义偏移”。解题者必须每一步都问：这是规则、提示，还是气氛？

### 55.6 评分系统的设计

`.entrance` 的进度分：

```text
0%   → 60
20%  → 61
40%  → 63
60%  → 66
80%  → 70
100% → 100
```

前五档是 `60 + n(n+1)/2`，第六档是特殊的 100。这样设计的结果：

- 完成四题时 70 分，处于 C；
- 完成五题直接 100，A+；
- 中间的 B（80–89）、A（90–99）在检查点评分下不可达。

这是有意的“跳变”：最后一题不是线性加分，而是从 C 直接跳到 A+。它强化了“Q5 是终点”的叙事。

提示系统则是另一套实时评分：初始 70，按 3、5、7、9、11、13、15 的原价、六折实扣。它让“买提示”成为真实的资源决策，而不是免费查看答案。

### 55.7 难度曲线

| 题 | 主要能力 | 难度 |
|---|---|---:|
| Q1 | 观察行长度与简单公式 | 低 |
| Q2 | 双规律（长度 + 周期 ±1） | 低–中 |
| Q3 | 递推 + 交替增量 | 中 |
| Q4 | 显式公式 + 诱饵答案 | 中 |
| Q5 | 程序逆向 + 编码还原 | 高 |

前四题的作用不是“难住人”，而是：

- 教会解题者数据格式；
- 建立“先看行长度，再看值”的习惯；
- 让解题者相信“规律是可找的”；
- 为 Q5 的“规律很多但机制只有一个”做反衬。

### 55.8 哪些地方可以更好

1. **Q5 的提示空间偏窄。** 七次提示都无法直接指向“索引驱动”，因为它们只能回答 T/F。可以考虑增加一条“元提示”，在连续两次“无效”后强制给出“换本体”的提示。
2. **`incipit.html` 容易被跳过。** 它承担叙事入口，但与解题链的连接较弱。可以在封面里放一个只有读完才会注意到的结构线索（例如文件层级图）。
3. **统计误导太强。** Q5 的局部规律（四阶差分、回返、LRU）足以支撑数小时的有效但错误的建模。这是设计上的成功，也是解题体验上的风险；可以在题面里加一句“数据是如何被计算出来的”作为方向提示，而不泄露机制。
4. **B/A 不可达。** 如果评分表是给人类看的，B/A 的空档会让人困惑。可以在 `.entrance` 里注明“检查点评分只覆盖部分档位”。

### 55.9 这个包真正想说什么

它想说的不是“数学很难”，而是：

> 结构也是内容。

一个文件为什么叫这个名字、为什么放在这一层、为什么用这个压缩格式、为什么留这个诱饵——这些都不是包装，而是题目的一部分。解题者不仅要算，还要判断“我现在在哪一层、这一层想让我做什么”。

Q5 是这一思想的极端形式：数据里充满了规律，但只有一条是生成规则。找到它，需要的不只是计算，还有放弃错误框架的勇气。

### 55.10 全书结语

从 `release/THE FRAGMENT.zip` 的第一层字节，到 Q5 生成器的最后一行，这个包用一条完整的链把“叙事、结构、数学、逆向”串在一起。

本书尽量保留了这条链上的每一个岔路：错误的列统计、被跳过的封面、被当成答案的嘲讽文本、被拟合出来的四阶差分。它们不是失败记录，而是题目的一部分。

如果读者只带走一件事，希望是：

> 先问“它是怎么被造出来的”，再问“它的规律是什么”。
