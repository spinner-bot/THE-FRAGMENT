# 第 0 部分 · 导读

> 本部分不解题。它只回答三个问题：这本书是什么、整个包是什么形状、后面反复出现的词是什么意思。

---

## 第 1 章：这本书是什么

### 1.1 三种文档，不要混在一起

关于《残卷》，至少可以写出三种完全不同的文档：

| 类型 | 回答的问题 | 典型内容 |
|---|---|---|
| 答案表 | 答案是多少 | 5050、K、五个公式 |
| 解题记录 | 某个人是怎么做出来的 | 尝试、失败、提示、修正 |
| 解题说明书 | 这个包为什么这样设计、每一步如何可复现 | 文件字节、算法、验证、设计意图 |

本书是第三种，但保留前两种的必要部分。

它不会只告诉你“答案是 5050”，而会说明：

- 5050 写在哪个文件的哪个字节里；
- 为什么这个答案必须写成 `5050` 而不是 `5,050`；
- 它如何被哈希成密钥材料；
- 锁如何验证这个答案；
- 如果答案错了，失败会以什么形式出现；
- 这个设计相对于“给 7z 加密码”好在哪里、弱在哪里。

同样，对于第 5 题，本书不会只贴出生成器代码，而会说明：

- 数据为什么看起来像动态系统；
- 哪些统计规律是真实的，但不是生成机制；
- 如何从 500 行数据反推到分组统计；
- 生成器的每一行如何对应数据中的每一列；
- 为什么“索引驱动”与“状态驱动”是两种不同的世界观。

### 1.2 剧透级别

本书是 **完全剧透**。它包含：

- 外层三题的全部答案与钥匙；
- P2 的 77 位整数 K；
- P3 的完整 payload；
- 内层五题的公式与第 5 题的生成器；
- 评分表、提示成本、诱饵答案的完整解释；
- 外部模型（ChatGPT）的解题记录与错误路径。

如果你还没有完成挑战，先离开。如果你只想核对某一个答案，直接去附录 E。

### 1.3 证据标准

本书尽量把结论分成三类，并在文中标明：

1. **字节事实**：可以直接由文件内容验证。
   例：`Q2.zst` 解压后第一行是 `ITC2RECIPE`；`the map.bmp` 的 17 个字节是 `answer is the key`。

2. **可计算事实**：可以由代码或数学复现。
   例：`5050 = 100×101/2`；`K` 的闭式公式与矩阵快速幂给出同一个值；第 5 题生成器复现 500/500 行。

3. **设计解释**：对“为什么这样设计”的合理说明，不是唯一答案。
   例：`incipit` 的六段文本对应外层三题；`.entrance` 的 B 不可达是刻意设计还是笔误。

第三类会用“可以这样理解”“一种解释是”之类的措辞，不冒充事实。

### 1.4 三种读法

**速查读法。** 只想知道答案：

1. 附录 E：五题答案速查；
2. 第 24 章：K 的值；
3. 第 27 章：P3 解锁后的结构。

**顺序读法。** 想完整走一遍：

1. 第 2–4 章：建立全局图；
2. 第 5–9 章：外层与 P1；
3. 第 10–17 章：锁的实现；
4. 第 18–25 章：P2；
5. 第 26–35 章：P3 与嵌套；
6. 第 36–50 章：五题与 Q5；
7. 第 51–55 章：复盘与设计。

**主题读法。** 只关心某一块：

- 密码学：第 10–17 章 + 附录 B；
- 数论：第 23–25 章 + 附录 C；
- 逆向工程：第 43–50 章 + 附录 D；
- 游戏设计：第 28–31、42、55 章；
- 外部解题记录：第 51–53 章 + `archive/chatgpt/timeline.md`。

### 1.5 与外部解题记录的关系

仓库里的 `archive/chatgpt/` 保存了两段 ChatGPT 解题对话的原始 JSON、HTML 和清洗稿。它们是：

- **解题者视角**的第一手材料；
- 验证“这个包对人类/模型是否可解”的样本；
- 展示错误路径、提示经济、统计陷阱的案例。

它们不是权威答案。ChatGPT 在第二段末尾明确承认：它把 Q5 错误地建模成动态系统，直到作者给出生成器代码才修正。本书会引用它的关键节点，但所有结论都以包内文件和可复现代码为准。

### 1.6 一个提醒

《残卷》有多处“多解释”设计：

- 说明书写着“五条警告中只有一条是真的”，但多条都可以被读成真；
- `.entrance` 的评分表在离散检查点与连续插值下给出不同的可达等级；
- `SHIT.README` 自称被损坏，但损坏本身是设计；
- 第 5 题的数据既有精确的四阶差分，也有精确的平方根关系，但两者都不是生成规则。

因此，本书的目标不是消灭歧义，而是 **把歧义放在正确的位置**：哪些歧义是谜题的一部分，哪些只是噪音，哪些会导致错误结论。

### 2.6 三个“不是”

理解这个包，需要先放弃三个直觉：

1. **扩展名不是格式。**
   `the map.bmp` 不是位图；`P1-02B` 不是二进制；`Q2.zst` 解压后不是 7z，而是文本锁。

2. **答案不是钥匙。**
   P1 的答案 5050 是钥匙；P2 的答案 K 是钥匙；但 P3 的内容不是“再开一个锁”，而是进入真正的挑战。`map.bmp` 说“answer is the key”，这句话是对的，但“key”不等于“你现在需要的那个答案”。

3. **说明书不是规则。**
   说明书写着“三道题”，但 P3 里面还有五道题；写着“只有一条警告是真的”，但多条都可能为真；写着“本说明书共 3 页，你正在读第 7 页”。它在训练你判断，而不是替你判断。

### 2.7 两条线：探索顺序与文件结构

这个包有两条同时推进的线，必须并排看：

- **探索顺序**：解题者按时间先后做了什么；
- **文件结构**：他此刻在嵌套树的哪一层。

只看探索顺序，容易把“解压步骤”当成“题目顺序”；只看文件结构，容易忽略“有些文件是给读者读的，不是给程序解的”。下表把两条线钉在一起。

1. **`incipit.html` 在结构上是最外层，但在探索顺序上可读可不读。** ChatGPT 的记录几乎直接进入 `Let's go`，这是合理的效率选择，但会错过“残卷”主题与“答案不在盒子里”的第一次提示。本书仍为它保留独立一章。

## 第 3 章：术语与符号

### 3.1 P 层与 Q 层

这个包有两套编号，容易混淆。

**P 层**是外层说明书使用的编号：

- **P1**：`Q1.tar` 里的 `1+2+...+100`；
- **P2**：`Q2.zst` 里的自描述锁 + SHIT 数学题；
- **P3**：`Q3.7z` 里的最后一题（锁 + 嵌套内容）。

**Q 层**是内层 `prompt.md` 使用的编号：

- **Q1–Q5**：原始五道二维数据题；
- 它们藏在 P3 的 `puzzle.7z` 里；
- 其中 Q5 是 500 行数据的生成器逆向。

外部解题记录（ChatGPT）使用“P3-Q5”这个混合叫法，意思是“P3 里面的第 5 题”。本书在需要严格区分时写作：

- `P1`、`P2`、`P3`：外层三题；
- `Q1`–`Q5`：内层五题；
- `P3-Q5`：只在引用外部对话时使用。

### 3.2 锁相关

| 符号 | 含义 |
|---|---|
| `marker` | 锁文件第一行 `ITC2RECIPE`，同时是 XOR 密钥 |
| `recipe` | 第二行十六进制 XOR 解码后的说明文本 |
| `body` | 空行之后的单个 base64 字符串 |
| `raw` | base64 解码后的字节串 |
| `CIPHER` | `raw` 去掉最后 16 字节的部分 |
| `TAG` | `raw` 最后 16 字节 |
| `D` | 当前锁的十进制答案（字符串形式参与哈希） |
| `S` | `SHA-256(ASCII(D))`，32 字节 |
| `STREAM_i` | `SHA-256(S ‖ uint64_be(i))`，第 i 个 32 字节密钥流块 |
| `K` | P2 的答案，77 位十进制整数，专名 |

### 3.3 “答案”“钥匙”“解”的区别

这三个词在本书中严格区分：

- **答案（answer）**：一道题问的那个东西。P1 的答案是 5050；P2 的答案是 K；Q5 的答案是生成器。
- **钥匙（key）**：用来打开下一个容器的字符串。P1 的答案同时是 P2 锁的钥匙；P2 的答案同时是 P3 锁的钥匙。
- **解（solution）**：完整的解题过程或生成机制，不一定是一个数。

`map.bmp` 说“answer is the key”，准确的读法是：

> 在这一层，答案恰好就是钥匙；但不要因此以为“找到钥匙”就等于“完成题目”。

### 3.4 容器相关

| 术语 | 含义 |
|---|---|
| 容器 | 任何承载下一层的文件：ZIP、7z、tar、gz、xz、bz2、zst、base64 文本 |
| payload | 锁或压缩包解开后的实际内容 |
| 诱饵答案 | 第 4、5 题 tar 里的 `1,010` 字节嘲讽文本 |
| 嵌套 | 容器里还有容器，直到最终题目 |
| 结构难度 | 由格式、命名、层级、误导造成的难度，而不是数学内容本身 |

### 3.5 评分与提示

| 术语 | 含义 |
|---|---|
| 进度 `k` | 0、0.2、0.4、0.6、0.8、1 |
| 评分 | `.entrance` 表中的 60、61、63、66、70、100 |
| 等级 | A+ 100、A 90+、B 80+、C 70+、D 60+、F 0+ |
| 提示成本 | 3、5、7、9、11、13、15 |
| `F` | 提示系统判定命题为假 |
| `Not a valid question` | 提问前提错误，不能当 `F` 使用 |
| 无法提供 | 系统拒绝回答，积分返还，成本不增加 |

### 3.6 文件命名中的方向

`P1-02C → P1-02B → P1-02A` 是倒序的。可以理解为：

- `C` 是最外层（最后被看到）；
- `B` 是中间层（base64 文本）；
- `A` 是最内层（实际内容）。

这不是标准版本号，而是叙事上的“倒着拆”。

## 第 4 章：解题总路线

### 4.1 一张决策树


### 4.2 三条原则

**原则一：先验证格式，再猜内容。**

不要根据扩展名决定用什么工具。正确顺序是：

1. 看文件头魔数（ZIP `PK`、7z `37 7A BC AF 27 1C`、gzip `1F 8B`、zstd `28 B5 2F FD`、xz `FD 37 7A 58 5A 00`、bzip2 `BZh`）；
2. 用对应工具试解；
3. 解不开再看扩展名和命名。

`Q2.zst` 的名字是对的（它确实是 zstd），但它解压后不是 7z；`P1-02B` 没有扩展名，但它是 base64；`the map.bmp` 扩展名是 `.bmp`，内容是文本。三种错位，三种训练。

**原则二：先读容器说明，再找工具。**

ITC2RECIPE 锁的第一行是 marker，第二行是 recipe。recipe 里已经写清楚：

- 用什么哈希；
- 怎么分帧；
- 怎么验证；
- 密钥从哪里来。

README 里说“这里没有现成的解密工具可以下载”，不是傲慢，是字面事实：工具必须由读者根据 recipe 写出来。

**原则三：先确认当前题，再解下一题。**

说明书反复强调“不能跳题”。这不是叙事装饰：

- P2 的锁只接受 P1 的精确答案；
- P3 的锁只接受 P2 的精确答案；
- 内层五题必须逐题通过。

跳题的后果不是“看到下一题”，而是“得到一堆看起来像数据的东西”。P3 的内容在没有 K 时就是密文；Q5 的数据在没有前四题训练时就是噪音。

### 4.3 五个常见卡点

| 卡点 | 错误做法 | 正确做法 |
|---|---|---|
| `Q2.zst` | 直接拖进 7z | 先用 zstd 解压，得到文本锁 |
| `P1-02B` | 当成二进制/加密数据 | 当 base64 文本解码 |
| `.entrance` | 当成可执行程序 | 当评分表阅读 |
| `第5题.答案` | 当成参考答案 | 识别为 1,010 字节诱饵 |
| Q5 数据 | 建立“下一列选择器”模型 | 先还原稀疏数组，再找分组统计 |

### 4.4 时间与难度预期

对一个熟悉命令行的解题者：

| 阶段 | 预计时间 |
|---|---|
| 外层 ZIP / 7z / gzip | 10–20 分钟 |
| P1 | 1 分钟 |
| 读锁 recipe + 写解密器 | 20–40 分钟 |
| P2 数学 | 20–40 分钟 |
| P3 解锁 + 嵌套拆解 | 30–60 分钟 |
| 内层 Q1–Q4 | 1–3 小时 |
| Q5 逆向 | 数小时到数天 |

Q5 的时间跨度最大，因为它不是“找到一个公式”，而是“排除多个错误模型”。外部解题记录用了约四小时，仍然在最后一步之前走错了框架。

### 4.5 本章的结论

这个包的设计可以概括为一句话：

> **答案链负责“能不能继续”，结构链负责“愿不愿意继续”，叙事链负责“相不相信继续”。**

三者缺一不可。只有答案链，它是一个普通的数学题；只有结构链，它是一个压缩包套娃；只有叙事链，它是一篇散文。三者叠加，才是《残卷》。
