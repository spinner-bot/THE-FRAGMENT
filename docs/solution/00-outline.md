# 《残卷》解题全书 · 详细大纲

本大纲是写作脚手架，也是读者的路线图。每一章都标出它要回答的问题、核心结论和证据来源。全书共 55 章，另附 6 个附录。

---

## 第 0 部分 · 导读（第 1–4 章）

### 第 1 章 这本书是什么

回答：这份文档为谁写、能读到什么程度、如何避免被剧透。

核心内容：

- 三种读者：想核对答案的、想复现解锁的、想研究设计的。
- 三种读法：速查、顺序、按主题跳读。
- 本书的“证据标准”：每个结论要么可由文件字节复现，要么由代码/数学验证，要么明确标为叙事解释。
- 与 `archive/chatgpt/` 的关系：外部解题记录是“解题者视角”的材料，不是权威答案。

### 第 2 章 全包一页图

回答：整个包到底是什么形状。

核心内容：

- 外层：`release/THE FRAGMENT.zip` → `incipit.7z` + `Let's go.7z`。
- 中层：`instruction.gz` + `Q1.tar` + `Q2.zst` + `Q3.7z`。
- 内层：P1 → 5050 → P2 锁 → K → P3 锁 → `.entrance` + `P1-02C` → 原始五题。
- 三条链：答案链（5050 → K）、结构链（压缩格式嵌套）、叙事链（残卷/说明书/警告）。
- 一张表：层级、文件、格式、钥匙、产出、失败模式。

### 第 3 章 术语与符号

回答：后面反复出现的词各指什么。

核心内容：

- P 层与 Q 层：外层三题叫 P1/P2/P3；内层五题叫 Q1–Q5，避免混淆。
- 锁、recipe、payload、CIPHER、TAG、marker、D、S、K。
- `D` 是当前锁的十进制答案；`S` 是它的 SHA-256；`K` 专指 P2 的 77 位答案。
- “容器自己说明自己”的含义：锁文件里同时包含方法说明、参数和密文。

### 第 4 章 解题总路线

回答：如果从零开始，先做什么、后做什么、什么时候该停。

核心内容：

- 决策树：看文件名 → 识别格式 → 解外层 → 读说明书 → 解 P1 → 读锁 → 解 P2 → 解 P3 → 拆嵌套 → 做五题。
- 三条原则：先验证格式再猜密码；先读容器说明再找工具；先确认当前题再解下一题。
- 常见卡点：把 `Q2.zst` 当成 7z、把 `P1-02B` 当成文本、把 `.entrance` 当成可执行程序、把 Q5 当成动态系统。

## 第 I 部分 · 入口与 P1（第 5–9 章）

### 第 5 章 release/THE FRAGMENT.zip：两层七件套

回答：最外层 ZIP 里到底有什么。

核心内容：

- ZIP 中央目录：`THE FRAGMENT/`、`incipit.7z`、`Let's go.7z`。
- 大小与哈希：28,828 字节；`e5e160e9…`。
- 为什么只有两个文件：一个负责“读”，一个负责“做”。
- 命名策略：`incipit`（序章）与 `Let's go`（开始）构成第一次叙事引导。

### 第 6 章 incipit：封面作为第零道题

回答：一个没有锁的 HTML 为什么也是谜题的一部分。

核心内容：

- `incipit.7z` → `incipit.html`，14,023 字节。
- 六段残卷文本的结构：缺失、气候、站进空缺、三次结束、注意力形状、保持敞开。
- “Three times the page ends before it should”对应外层三题。
- 封面不提供答案，但提供阅读姿态：慢读、接受残缺、不要寻找完整。

### 第 7 章 Let's go.7z 与 instruction.gz：说明书层

回答：真正的入口包如何组织。

核心内容：

- `Let's go.7z` 的五个条目：`instruction.gz`、`Q1.tar`、`Q2.zst`、`Q3.7z`、目录。
- `instruction.gz` 解压后 17,872 字节，是一份带 CSS 动画的 HTML 说明书。
- 说明书的三层结构：规则（R1–R6）、题目形状（P1–P3）、警告（W1–W5）。
- 为什么说明书本身要“不可信”：它在训练读者区分指令、噪音与叙事。

### 第 8 章 说明书的真假语法

回答：R1–R6、W1–W5 和附录哪些是有效规则，哪些是气氛。

核心内容：

- R1–R6 中可操作的部分：十进制、精确答案、无现成工具、完整性校验、不信名字。
- W1–W5 的“只有一条是真的”是一个不可判定的叙事声明；逐条分析其可能含义。
- W1 与诱饵答案的对应；W4 与 `map.bmp` 的对应；W2 与嵌套结构的对应。
- 附录大量无意义段落的功能：耗尽“寻找隐藏信息”的冲动，让读者回到文件本身。

### 第 9 章 P1：5050 与答案规范化

回答：第一题为什么这么简单，答案如何成为钥匙。

核心内容：

- `Q1.tar` → `Q1/Q1`，内容 `1+2+3+4+......+100=?`。
- 等差数列求和：`100×101/2 = 5050`。
- 答案规范：纯十进制、无空格、无分隔符、无前导零。
- 为什么用 5050：它是最低门槛的“开始”，同时是一个容易被写错格式的答案。
- 5050 作为 P2 锁的 `D`，进入 `S = SHA-256("5050")`。

## 第 II 部分 · 自描述锁 ITC2RECIPE（第 10–17 章）

### 第 10 章 ITC2RECIPE：一个文件如何描述自己

回答：这个锁的整体格式是什么。

核心内容：

- 第一行 `ITC2RECIPE`；第二行十六进制 recipe；空行；base64 body。
- 锁文件本身是一份“可执行的说明书”：读它就能写出解密器。
- 设计目标：不依赖 7z 密码框、不发布解密工具、错误钥匙必须明确失败。
- 与普通加密压缩包的区别：方法公开、密钥保密、完整性校验内置。

### 第 11 章 Marker 与 recipe：XOR 的可逆性

回答：第二行的十六进制如何变成明文说明。

核心内容：

- `marker = b"ITC2RECIPE"`，长度 10。
- `recipe[i] = hex[i] XOR marker[i mod 10]`。
- 逐字节演示前 32 字节的解码结果。
- 为什么用 XOR 而不是再套一层加密：这是“可读性”设计，不是保密设计。

### 第 12 章 Body：base64、CIPHER 与 TAG 的分帧

回答：base64 解出来的一串字节如何分成密文和校验码。

核心内容：

- body 是单个 base64 字符串，允许换行。
- 解码后 `raw = CIPHER || TAG`，`TAG` 固定 16 字节。
- `CIPHER` 长度必须是 32 的倍数（最后一块可短）。
- 分帧错误会导致 TAG 校验失败，因此不要先解密再猜边界。

### 第 13 章 密钥派生：S = SHA-256(ASCII(D))

回答：答案如何变成 32 字节密钥材料。

核心内容：

- `D` 是十进制字符串，不是整数本身；`5050` 与 `"5050"` 的字节不同。
- `S = SHA-256(D.encode("ascii"))`。
- 为什么先哈希：把任意长度的答案压成固定 32 字节，并隐藏答案长度。
- 错误答案的后果：`S` 不同 → 流不同 → TAG 失败。

### 第 14 章 块流：SHA-256(S ‖ uint64_be(i))

回答：没有 AES，如何生成足够长的密钥流。

核心内容：

- 每个 32 字节块 `i` 的流：`SHA-256(S || uint64_be(i))`。
- 计数器从 0 开始，大端 8 字节。
- 逐块 XOR；最后一块按实际长度截断。
- 这不是标准流密码，但对本挑战足够；安全性来自答案空间与 TAG，而不是算法强度。

### 第 15 章 验证：Encrypt-then-MAC

回答：如何判断钥匙是否正确，且不信任错误明文。

核心内容：

- `EXPECTED = SHA-256(S || 0x02 || CIPHER)[:16]`。
- 先比较 TAG，再解密；顺序不能反。
- 错误钥匙会产生“看起来像数据”的垃圾，这是设计上的失败模式。
- 16 字节截断的碰撞概率与安全性讨论。

### 第 16 章 最小解密器：从零实现

回答：如何用几十行 Python 打开任意一把 ITC2RECIPE 锁。

核心内容：

- 完整代码：读文件、拆行、XOR recipe、base64、分帧、TAG 校验、块流解密。
- 逐行解释每个边界条件。
- 用 5050 和 K 分别测试。
- 输出文件的 SHA-256 与 7z 魔数验证。

### 第 17 章 设计评估：为什么不用 7z 密码

回答：这个自描述锁相比现成加密工具好在哪、弱在哪。

核心内容：

- 优点：方法可见、可审计、无工具依赖、错误钥匙有明确失败、叙事一致。
- 弱点：流密码是自定义构造、TAG 截断、答案空间可能被暴力枚举。
- 适用边界：这是谜题容器，不是生产加密。
- 如果重做：HKDF、全 32 字节 MAC、答案加盐。

## 第 III 部分 · P2：SHIT 层（第 18–25 章）

### 第 18 章 Q2.zst：zstd 与第一把锁

回答：为什么第二题的文件名是 `.zst`，里面却不是压缩包。

核心内容：

- `Q2.zst` 是 zstd 帧，解压后得到 `ITC2RECIPE` 文本。
- 文件扩展名与真实格式的第一次错位。
- 如何识别 zstd 魔数 `28 B5 2F FD`。
- 解压后大小 5,356 字节。

### 第 19 章 用 5050 打开 Q2

回答：锁打开后得到什么。

核心内容：

- `D = 5050`，`S = SHA-256("5050")`。
- TAG 校验通过；解密得到 2,187 字节的 7z。
- 7z 内含 `Q2/SHIT.tar.xz` 与 `Q2/the map.bmp`。
- 第一次“答案变成钥匙”的完整闭环。

### 第 20 章 Q2 payload：SHIT.tar.xz 与 map.bmp

回答：两个文件各自的角色。

核心内容：

- `SHIT.tar.xz`：1,960 字节，内含 `SHIT.README` 与 `SHIT.bz2`。
- `the map.bmp`：17 字节，内容 `answer is the key`，不是位图。
- 文件名的误导：`.bmp` 是文本，`.tar.xz` 是真正的容器。
- W4 的对应：答案是钥匙，但钥匙不是答案。

### 第 21 章 SHIT.README：可读的噪音

回答：这份故意写坏的文件里，哪些信息可信。

核心内容：

- 2,584 字节，拼写错误、重复、自指、矛盾指令。
- 可提取的真实信息：`M = 2^255 - 19`、`N = 10^18`、`C` 被涂掉。
- 不可信信息：行号、文件名、校验和、长度、“答案不在任何文件里”。
- 噪音设计的原则：让读者读完，但不让读者从中直接得到公式。

### 第 22 章 SHIT.bz2：真正的题面

回答：第二题的数学问题到底是什么。

核心内容：

- bzip2 解压后 665 字节的纯文本。
- 递推：`x_0 = 1`，`x_{n+1} = (3x_n + C) mod M`。
- `C` 的 77 位十进制值；`N = 10^18`。
- 答案格式：精确十进制整数，无分隔符。
- 提示：仿射映射的 N 次复合仍是仿射映射。

### 第 23 章 仿射递推：从 10^18 次到一次幂

回答：如何在不迭代 10^18 次的情况下求 `x_N`。

核心内容：

- `f(x) = 3x + C`。
- `f^N(x) = 3^N x + C(3^N - 1)/2`。
- 模 `M` 下的除法：乘以 2 的逆元。
- 快速幂 `pow(3, N, M)`；复杂度 `O(log N)`。
- 为什么不能直接算 `3^N`：数字太大，必须先取模。

### 第 24 章 K 的计算：77 位整数

回答：K 的具体值与计算过程。

核心内容：

- `K = 55570866527475159802584688178377681056129853902315582853460115578675137387640`。
- 十六进制：`0x7adbfeef3a37490e4bd46bb6fca3c1690005d6e1c30a798820ee733de3fc9c78`。
- 77 位十进制、32 字节。
- 计算脚本与中间量 `3^N mod M`。

### 第 25 章 K 的独立验证与交接

回答：如何确认 K 不是抄错或算错。

核心内容：

- 方法一：闭式公式；方法二：2×2 矩阵快速幂；两者一致。
- 方法三：用 K 打开 Q3 锁，TAG 通过。
- 答案交接：K 作为 Q3 锁的 `D`，`S = SHA-256(str(K))`。
- 注意：K 的十进制字符串不能有空格、换行或前导零。

## 第 IV 部分 · P3 与嵌套结构（第 26–35 章）

### 第 26 章 Q3.7z：README 与锁

回答：第三题的外层是什么。

核心内容：

- `Q3.7z` 内含 `Q3/README.txt` 与 `Q3/is this the true challenge == false`。
- README：181 字节，提示“完成第 2 题才能解锁第 3 题”。
- 锁文件名本身是一句话，也是叙事挑衅。
- 15,682 字节的锁文件，仍是 ITC2RECIPE 格式。

### 第 27 章 用 K 打开 Q3

回答：第三把锁打开后得到什么。

核心内容：

- `D = K`，TAG 校验通过。
- 解密得到 9,831 字节的 7z。
- 内含 `.entrance`（416 字节）与 `P1-02C.7z`（9,206 字节）。
- “最后一题”并没有结束，而是进入更深的嵌套。

### 第 28 章 .entrance：评分表逐行

回答：这份 416 字节的文本到底在说什么。

核心内容：

- 进度提示：0%、20%、40%、60%、80%、100%。
- JSON 风格的评分表：`0:60`、`0.2:61`、`0.4:63`、`0.6:66`、`0.8:70`、`1:100`。
- 等级：A+ 100、A 90+、B 80+、C 70+、D 60+、F 0+。
- 结语：“So you can never got a B.”
- HTML 实体 `&#x09;` 是制表符，说明它曾是网页/表格的一部分。

### 第 29 章 评分函数：60 + k(k+1)/2

回答：前五个评分点背后的公式。

核心内容：

- 差值：1、2、3、4。
- `score(k) = 60 + k(k+1)/2`，`k = 0, 0.2, 0.4, 0.6, 0.8`。
- 第六个点 `k=1` 突然跳到 100，不遵循二次公式。
- 分段函数：`[0,0.8]` 用二次式，`1` 用特例。
- 评分不是连续进度，而是六个检查点。

### 第 30 章 为什么永远拿不到 B：可达等级分析

回答：等级表的“不可达”是 bug 还是设计。

核心内容：

- 六个可达分数：60(D)、61(D)、63(D)、66(D)、70(C)、100(A+)。
- 80–89（B）与 90–99（A）没有采样点。
- 若只允许检查点结算：B、A、F 不可达。
- 若允许连续插值：B、A 可达，但 `score` 在 0.8 到 1 之间没有定义。
- 结论：这是一个“多解释”的终端谜题，不是可执行的评分器。

### 第 31 章 提示经济：F、无效与无法提供

回答：提示系统的三种回应分别意味着什么。

核心内容：

- `F`：命题为假，能否定一个具体假设。
- `Not a valid question`：提问前提错误，不能当 `F` 用。
- `无法提供`：系统拒绝回答，积分返还，成本不增加。
- 提示成本：3、5、7、9、11、13、15。
- 最优策略：只在候选机制可区分时购买；开放式提问容易触发“无效”。

### 第 32 章 P1-02C → P1-02B：base64 文本伪装

回答：为什么一个 7z 里只有一个没有扩展名的文本文件。

核心内容：

- `P1-02C.7z` 只含 `P1-02B`。
- `P1-02B` 是 11,900 字节的 base64 文本，解码后 8,923 字节。
- 解码结果以 `PK\x03\x04` 开头，是 ZIP。
- ZIP 内含 `P1-02A/content.tar` 与 `P1-02A/README.7z`。
- 命名 `P1-02C/B/A` 是倒序的层级标记。

### 第 33 章 P1-02A：content.tar 与 README.7z

回答：两个并行分支各自提供什么。

核心内容：

- `content.tar`：9,728 字节，内含一个 33 字符目录名（31 位整数 + `.5`）。
- `README.7z`：1,451 字节，内含 `README/README.json`。
- 两条线索：一条通向题目，一条通向“元文本”。
- 为什么要把 README 单独加密：让读者在拆题之前先读一段“拒绝说明”的文字。

### 第 34 章 31 位整数目录名与 README.json 码点

回答：这些看似无意义的数字和数组如何解读。

核心内容：

- 目录名 `1000000000000000000000000000001.5` = `10^30 + 1.5`，不是合法版本号。
- `README.json` 是 2,245 个 Unicode 码点的数组。
- 解码后是一段 2,245 字符的全大写英文长文本。
- 文本主题：拒绝被定义、拒绝形状、拒绝确定性；与“残卷”叙事一致。
- 它不是答案，但它是设计声明。

### 第 35 章 prompt.7z 与 puzzle.7z：原始五题

回答：嵌套的终点是什么。

核心内容：

- `prompt.7z`：`prompt.md` 与 `prompt.html`，原始五题挑战说明。
- `puzzle.7z`：第 1–3 题纯文本，第 4–5 题 tar 包。
- 第 4 题 tar 内含题目与 1,010 字节的诱饵答案。
- 第 5 题 tar 内含 `第5题.7z` 与同样的诱饵答案；真正的 500 行数据在 7z 内。
- 两个诱饵答案字节完全相同，哈希 `b1a558e2…`。

## 第 V 部分 · 五题数据挑战（第 36–42 章）

### 第 36 章 数据格式与解析器

回答：`[index][content]` 到底怎么解析。

核心内容：

- 每行 `[n][a,b,c,...]`；部分空格/空字符不一致。
- 用正则 `^\[(\d+)\]\s*\[(.*)\]$` 提取。
- content 是逗号分隔整数，允许负数。
- 写一个 20 行解析器，输出 `list[list[int]]`。
- 验证行数、列数、最大/最小值。

### 第 37 章 第 1 题：三角数分块

回答：第 1 题的生成公式。

核心内容：

- 行 `n` 有 `n` 个数，从 `T_{n-1}+1` 到 `T_n`。
- `a(n,k) = n(n-1)/2 + k`，`k=1..n`。
- 验证第 6 行：16–21。
- 设计意图：最简单的“看规律”热身。

### 第 38 章 第 2 题：Fibonacci 长度与周期 ±1

回答：第 2 题的两个独立规律。

核心内容：

## 第 VI 部分 · 第 5 题逆向工程（第 43–50 章）

### 第 43 章 数据形态：500 行、12 字段、负数游程

回答：第 5 题的原始数据长什么样。

核心内容：

- 统计：488 次有效更新、242 个连续更新区段。

### 第 44 章 第一层还原：稀疏数组

回答：如何把负数游程还原成真正的数组。

核心内容：

- `-k` 表示接下来 `k` 个零。
- 例：`[-1,4,8]` → `[0,4,8]`。
- 例：`[-3,34]` → `[0,0,0,34]`。
- 还原后长度可变；每一行是一个稀疏向量。
- 还原脚本与验证。

### 第 45 章 三角数编码：(l+s)(l+s+1)/2+s

回答：每个非零值如何编码一个分组的“数量”和“和”。

核心内容：

- 设某分组有 `l` 个元素，元素和为 `s`。
- 编码值 `V = (l+s)(l+s+1)/2 + s`。
- 这是把 `(l,s)` 对映射到整数的双射（在可达范围内）。
- 如何从 `V` 反解 `(l,s)`：解三角数不等式。
- 为什么用三角数：紧凑、可逆、不易一眼看穿。

### 第 46 章 Collatz 计数 C(n) 与 round R(n)

回答：分组键从哪里来。

核心内容：

- `step(n)=3n+1`（奇）或 `n/2`（偶）。
- `C(n)`：从 `n` 到 1 的项数，`C(1)=1`。
- `R(n)=C^{C(n)-1}(C(n))`：对 `C(n)` 再迭代 `C(n)-1` 次。
- 例：`C(1)=1`，`R(1)=1`；`C(2)=2`，`R(2)=C(2)=2`。
- 分组键是 `R(m)`，不是 `C(m)`。

### 第 47 章 calc 的控制流：三个递归分支

回答：那段混淆代码到底怎么运行。

核心内容：

- 三个分支：继续累积、输出压缩数组、初始化分组集合。
- `m` 是当前索引；`s` 是分组字典；`u` 是 `(k,l,s)` 集合；`v` 是输出向量。
- 条件 `not (bool(m-n-1) ^ bool(m or v))` 的含义。
- 为什么代码看起来像“状态更新”，实际是“对每个 n 重新计算”。

### 第 48 章 分组统计与“相邻行只变一列”

回答：为什么数据看起来像动态系统。

核心内容：

- `B_k(n) = {m ≤ n : R(m)=k}`。
- `B_k(n)=B_k(n-1)`，除非 `R(n)=k`。
- 所以相邻两行只有一个分组变化。
- 这是“批量计算”的副作用，不是“选择下一列”的规则。
- 488 次更新 = 488 个需要加入分组的 n。

### 第 49 章 从数据反推：差分、平方根、三角数、分桶

回答：不看答案代码，能否从数据走到正确模型。

核心内容：

- 第一步：还原稀疏数组，发现非零位置固定。
- 第二步：对连续更新区段做差分，发现四阶差分/平方根关系。
- 第三步：把值反解成 `(l,s)`，发现三角数编码。
- 第四步：把 `l` 与 `s` 解释为分组计数/和。
- 第五步：寻找分组键；Collatz 是候选之一。
- 这条路径的难点：每步都有多个等价解释，必须用全量数据验证。

### 第 50 章 正确模型：索引驱动，不是动态系统

回答：Q5 的最终算法是什么。

核心内容：

- 对每个 `n`，独立计算 `1..n` 的 `R(m)`。
- 按 `R(m)` 分组，统计 `N_k`、`S_k`。
- 用三角数编码生成稀疏向量。
- 压缩零游程，输出。
- 没有随机数、没有隐藏状态、没有“下一列选择器”。
- 500/500 行复现验证。
